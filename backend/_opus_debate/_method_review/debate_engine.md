# Methodology Audit — Multi-Agent Debate Engine (Radar / Interrogator / Architect / CRO)

Reviewer: Fable 5, senior quant-methodology pass, 2026-07-01.
Scope: `backend/live_debate_engine.py` (nightly/production 4-agent path), `backend/weekly_opus_refresh.py` (`_WORKFLOW_TEMPLATE` — the weekly Claude-Code single-agent-per-name path), `backend/_opus_debate/{interrogator,architect,moderator}_system.txt`, `secular_themes.json`, `_post_common.py`, `_value_post.py`, `_regime_post.py`.
Audited AGAINST the proven evidence: 0/407 verdict-A on the priced-quality funnel vs 10 verdict-A on the 17-name B13 catalyst funnel; skeptic-as-cap bug; freshness gap on ad-hoc paths (87% CORRECTIONS); GDOT kill-tier proof.

## 1. WHAT WORKS (keep — and why it earns its complexity)

1. **Skeptic verdict-based demotion with a staleness guard** (`_post_common.py:19-74`, consumed by `_value_post.py:100` and `_regime_post.py:77`). REFUTED physically demotes to `runner_ups`; shards older than the apex file are ignored so a stale verdict can never demote a fresh basket; the sidecar merge is idempotent. This is the one genuinely adversarial seat in the system and it has proven teeth (GDOT: CRO said A/5, skeptic REFUTED the thin arb). Earns its complexity because the deterministic guardrails are exactly where LLM pipelines silently rot.

2. **Fail-closed interrogator credibility** (`live_debate_engine.py:1307-1330`). A malformed dossier retries once for the machine line, then scores `None`, which `value_input()` maps to gate=CAP (`weekly_opus_refresh.py:699-703`) — fail toward caution, never a silent neutral 3 above the EXCLUDE gate. The forensic gate itself (credibility<=2 → EXCLUDE, regime-independent, `weekly_opus_refresh.py:697-707`) is the pipeline's most defensible hard filter, and the **ledger re-check path** (`_WORKFLOW_TEMPLATE` `recheckPrompt`, :2888-2892) re-affirms unexpired exclusions with a short web pass instead of a full re-debate — a real cost saver that preserves the veto's memory.

3. **Targeted data-defect overrides, date-stamped** — `_ttm_block` (:878-931, "as of <date> — USE THESE OVER THE FISCAL-YEAR-ANNUAL") and `_live_corrections` (:934-993, net-debt sign-flips + grant-inflated insider "buys"). These fix the two audit-proven worst scan fields at debate time rather than waiting a scan cycle, and they carry explicit instructions on how to use them (never add net debt back as "net cash"). Cheap, surgical, honest.

4. **`_slice_transcript` head+tail preservation** (:840-856). 55/45 head/tail keeps the analyst Q&A — where evasion and guidance-delivery signal live — instead of a naive head slice. Small function, large forensic payoff.

5. **Radar as tagger-not-gate on the nightly path** (:1284-1286) with fail-open on API error (:1278-1282). No candidate is silently dropped by the cheapest model in the stack. (But see W3 — the tag still carries a hidden kill-switch through the moderator prompt.)

6. **Chunked Radar peer-comps with live-anchor overrides** (weekly: `_WORKFLOW_TEMPLATE` Phase 0, :2853-2866; `PEER_OVERRIDES` restamp `weekly_opus_refresh.py:304-447`). ≤20 names per Sonnet agent (a single agent provably truncates at 161 names), deterministic merge, `unmapped` escape hatch for unrecognized tickers, `peer_override/anchor_multiple` as the live de-rated anchor, and the `convergence="sector_regulatory"` tag that stops "cheap vs a peer that de-rated on the same factor" being credited as alpha (the Edenred/Pluxee trap). This is the best prompt-engineering in the repo: it names the exact failure mode and gives the agent the corrected input.

7. **Deterministic post-processing owns the teeth, not the prompts** — moat half-cap (`moat_per_name_cap`, `_post_common.py:128-134`), secular-theme concentration caps with the durable-anchor half-count (`secular_theme_caps`, :106-125; vocabulary controlled by `secular_themes.json`), measured 2y correlation breach caps (`_value_post.py:317-341, 387-394`), market-based stress with a bear-case-invalid flag (:260-290). Sizing consequences live in code where they are reproducible and auditable; the prompts only tag.

8. **`catalyst_status` discipline** (moderator_system.txt:61; weekly step 5 web-verification mandatory for every name, :2879). The FIRED/ARB/PENDING_HARD/SOFT_EXTENDED/UNVERIFIABLE enum with "NEVER assert a live status you cannot source" and uniform application is what caught the MYRG staleness kill; UNVERIFIABLE as the honest default is the right fail direction.

9. **The single-agent-per-name weekly design** (`debatePrompt`, :2870-2883) is the right economic call, not a compromise to apologize for: one Opus agent per name playing Interrogator→Architect→CRO sequentially costs 1 agent instead of 3-4, stays inside the >16-wide rate-limit ceiling at BATCH=8, and gets shared web context across the seats. The independence it sacrifices (see W6) is recovered where it matters — at the separately-spawned, bear-only Skeptic.

## 2. WEAKNESSES / RISKS

### W1 — PROVEN: conviction is hard-coupled to the verdict letter; the 1-5 scale is a recoded A/B/C, and conviction-5 is unreachable by construction on a priced tape.
Evidence: `live_debate_engine.py:783-788` / `moderator_system.txt:68-73` — "The conviction score MUST be an integer between 1 and 5 **matching the verdict**: 5 = Strong Buy (Aggressive Entry…) / 4 = Buy (Watchlist…) / 3 = Hold / 2 = Sell (Pass…) / 1 = Strong Sell (Pass…)". Verdict A requires "catalyst imminent, market offside" (:779), which the regime brief further restricts to below-SoP + live un-fired catalyst. So for a priced-quality compounder the ceiling is B→4 in theory, 3 in practice, and the modal 2 is just "C". The 0/407 conviction-5 result is not a calibration mystery — it is the rubric's definition. Downstream, everything gates on this echo: `select_methodology_basket` filters conviction>=3 (:1412), the apex Director's "Eligible = conviction >= 3" (`_WORKFLOW_TEMPLATE` STEP 3, :2912). The 5-point scale adds no information beyond the 3-letter verdict; it *looks* like a confidence dial but is a timing call. Failure caused: the funnel-composition bottleneck (proven) is enforced at the gate, and any consumer treating conviction as confidence (UI, sorting, the value-input fallback when `value_conviction` is null, `weekly_opus_refresh.py:550`) inherits the timing tilt.

### W2 — PROVEN (latent crash): the 8f fail-closed `interrogator_score=None` breaks the nightly basket sort.
Evidence: `live_debate_engine.py:1320/1330` set `result["interrogator_score"] = None` on parse failure; `select_methodology_basket` sorts with `key=lambda x: (-x.get("conviction", 0), -x.get("interrogator_score", 0))` (:1415). `dict.get` returns the stored `None` (the default only applies to a *missing* key), and `-None` raises TypeError — a name that failed dossier parsing but got moderator conviction >=3 crashes the entire tier-1 run. The two fixes (8f fail-closed, added later) and this sort were never reconciled. The nightly debate is currently env-gated OFF on Cloud Run, so this bites the next local/backfill tier-1 run — the worst kind of bug: dormant until the day you need the fallback path.

### W3 — PROVEN: the signal-type "trap cap" hands a kill-switch to the cheapest model on the nightly path, and on the weekly path signal_type is not a radar read at all.
Evidence: moderator prompt (:815 / moderator_system.txt:100): "If signal_type is 'trap' or 'none': assign conviction ≤ 2 and verdict C unless extraordinary override evidence exists." On the nightly path that tag comes from gemini-3.5-flash reading ONE truncated transcript (:1263-1272), and `RADAR_GROWTH_CATALYST_PROMPT` (:667-685) returns "none" for any company without innovation/event vocabulary — i.e., for every boring priced-quality compounder, by design. So a flash-model single-pass read mechanically consigns exactly the quality names to ≤2 before the Opus dossier is even weighed. On the weekly path, `signal_type` is derived from methodology membership (`weekly_opus_refresh.py:2738`: `"deep_value" if all value-methods else "catalyst"`) — every non-value name is labeled "catalyst" whether or not a catalyst exists, so the CRO judges compounders through a catalyst-timing lens and scores them 2-3 for lacking one. Both paths converge on the same failure: the modal-2 ceiling is partly *framing*, not just funnel composition.

### W4 — PROVEN: the moat-erosion cap at value_conviction<=3 is blunt and double-punishes.
Evidence: moderator prompt (:794 / moderator_system.txt:79, weekly step 6 :2880): "an ERODING moat … OR a TERMINAL secular threat CAPS value_conviction at 3." Three problems: (a) one threshold for two very different severities — a mild-erosion name at a 50% MoS and a melting ice cube both cap at 3, compressing exactly the deep-value tail the value book exists to buy; (b) ERODING is judged from *trailing* returns/margin trend (Interrogator section 8, `interrogator_system.txt:74`), which fires on cyclical margin dips — the prompt itself admits the distinction ("distinct from a cyclical dip") but gives the agent no test to apply; (c) the deterministic post *already* half-sizes eroding-moat names (`moat_per_name_cap`) and `erosion_severity="value-destroying"` is already apex-ineligible (`VALUE_DIRECTOR_PROMPT`, :567) — so the same signal cuts the name three times (score cap → size cap → eligibility), a softer echo of the proven skeptic-as-cap bug: numeric caps stacked on verdict gates crush scores.

### W5 — PROVEN (residue of the skeptic-as-cap bug): the Skeptic is still asked for a numeric `value_conviction_cap`, which is stamped and published but enforced nowhere.
Evidence: both skeptic workflow generators still demand it (`weekly_opus_refresh.py:1283-1284` value, :1332-1333 regime); `consume_skeptic` stamps it onto the pick (`_post_common.py:56-57`, `_value_post.py:138-139`); `publish_to_frontend.py:247` ships it to the UI. Nothing in the backend applies `min(conviction, cap)` — the verdict-based demotion correctly replaced it. Failure caused: (a) skeptic effort is spent anchoring a number that proven-empirically clusters at 2-3 regardless of thesis quality (see `_skeptic_results.json` — 11 caps: mode 2-3), (b) the UI displays a "cap" that the system does not honor — a silent honesty gap, (c) a future maintainer will find the field populated and "fix" the missing enforcement, reintroducing the proven bug.

### W6 — SUSPECTED: the weekly "debate" is a monologue with hats, and only finalists ever meet an adversary.
Evidence: `debatePrompt` (:2874-2882) has ONE agent produce the dossier, then the bull/bear, then the CRO reconciliation, sequentially in the same context. A model that just wrote an evidence-rich bull case exhibits self-consistency bias when asked to grade it two steps later; the Architect/CRO "independence" is stylistic. The real check — the bear-only Skeptic with primary-source verification — runs only on apex *finalists* (`SKEPTIC` workflows are generated over the finalists list, :1289). The ~150 non-finalists get zero adversarial review, which matters because the Director's runner-up pool and the value book's full-input grade (`value_input` reads ALL of results_regime) both consume unadversarial scores. Cannot be proven from artifacts without a seat-split A/B, hence SUSPECTED — but the 87% CONFIRMED_WITH_CORRECTIONS rate on ad-hoc names shows how often a single-context pass carries a wrong load-bearing number.

### W7 — PROVEN: durable Director prompts are contaminated with dated, name-specific instructions.
Evidence: `VALUE_DIRECTOR_PROMPT` (`weekly_opus_refresh.py:569-571`) hard-codes "call out BRBR and CALM EXPLICITLY", "Known live clusters to check EXPLICITLY: THC+UHS …; CMCSA+SAX.DE …; PLX.PA/Pluxee vs a now-~10x Edenred", "note ARDT re-clusters with hospitals, SREN.SW with SCR.PA". These were correct on 2026-06-09; they are instructions in a *reusable* prompt. Failure caused: a future run whose pool lacks BRBR/CALM is still ordered to discuss them (the agent either hallucinates a mention or wastes memo space explaining their absence), and the anchor multiples ("now-~10x Edenred") go stale the same way the prompt itself warns peer multiples do. The rest of the machinery (peer_override restamps, prior-run measured correlations appended at `value_input`, :766-778) already generates fresh context correctly — the hard-coded examples fight it.

### W8 — SUSPECTED: Interrogator/CRO section redundancy inflates cost and produces duplicate, occasionally contradictory reads.
Evidence: Interrogator §5 "Analyst pressure points" (:726-727) substantially pre-writes the CRO's `consensus_delta` (:767); Interrogator §8 derives moat/moat-trend/secular-threat (:735-741) and the CRO is then asked to emit the same three fields "reconciled" (:795-797) — two moat reads per name that `value_input` then cross-checks against a THIRD deterministic read (`_moat_features`). On the nightly 3-model path the most-recent 18k-char transcript is sent to all three of Interrogator, Architect (:1339), and Moderator (:1365) — roughly 3× the transcript tokens per name; with an Opus interrogator at 5-8 quarters × 18k chars plus a 12k-token output cap, the nightly cost is plausibly $1.5-2.5/name, ~$300-400 per 160-name universe, dominated by the Interrogator. On the weekly path duplication is free (one context) but the dossier tokens still count against the resume-cycle budget on a multi-hour run.

### W9 — PROVEN (by the funnel evidence) : peer_groups and the freshness stamps exist only on the weekly path; ad-hoc/nightly debates run un-anchored.
Evidence: `debate_candidate` (nightly) never reads `peer_groups/` (no reference anywhere in `live_debate_engine.py`); the ad-hoc lane (`_adhoc_debate.js`, `publish_adhoc.py`) carries `peer_comps_note` fields but no pre-injected dated metrics — which produced the 87% corrections rate and the MYRG staleness kill on exactly those paths. The analyst-consensus line in the metrics block (:1130-1136) carries no as-of date at all. The engine's own comments prove the failure class is known (`_ttm_block` docstring: "stale in 97% of audited names"); the fix was applied to one path and not the others.

## 3. PROPOSALS (ranked)

### P1. [RETURN] Decouple conviction from verdict — or delete the CRO's 1-5 conviction outright.
**Change:** In `MODERATOR_SYSTEM_PROMPT` (`live_debate_engine.py:783-788`), `moderator_system.txt:68-73`, and `_WORKFLOW_TEMPLATE` step 6 (:2880): replace "MUST match the verdict" with an independent definition — *conviction = confidence the reconciled SoP/thesis is right at this price over the stated horizon, orthogonal to entry timing; a verdict-B name with an overwhelming value case IS a 5*. Re-anchor each level behaviorally (5 = below adverse-SoP with verified floor; 4 = below base SoP, thesis skeptic-survivable; 3 = fair; 2 = rich or unverifiable; 1 = trap/impaired). Change the two eligibility gates (`select_methodology_basket:1412`, Director STEP 3 :2912) to `verdict in (A,B) OR value_conviction >= 3`. Keep the old field emitted for one cycle for comparability.
**Impact:** honest — this will NOT mint alpha by itself (the funnel fix already shipped); what it does is stop the gate from censoring priced-quality names the *value* book wants, make the score mean something downstream, and let the new special-sit lane's 4-5s coexist with quality 4s instead of the scale being a catalyst-o-meter. Expect the conviction distribution to de-degenerate (modal 2 → a real spread), which also makes future calibration measurable.
**Effort:** M (3 prompt surfaces + 2 gate lines + regenerate `_weekly_debate.js`). **Risk:** breaks time-series comparability of `conviction`; a looser gate lets more mediocre names reach the Director (mitigated: the Director re-scores 0-100 and the skeptic still demotes).

### P2. [SAFETY] Fix the None-score sort crash.
**Change:** `live_debate_engine.py:1415` → `key=lambda x: (-(x.get("conviction") or 0), -(x.get("interrogator_score") or 0))`. Audit the other consumers of `interrogator_score` for the same None (memo building :1424-1428 is safe; `run_tier1` stats are safe).
**Impact:** removes a guaranteed crash of the next tier-1/backfill run on the first malformed dossier with conviction>=3. **Effort:** S. **Risk:** none.

### P3. [RETURN] Grade the moat cap; collapse the triple-punishment to two layers.
**Change:** In the three prompt surfaces carrying the cap (moderator prompt :794, moderator_system.txt:79, weekly step 6 :2880): (a) tier it — TERMINAL secular threat or `value-destroying` erosion → cap 2; ERODING alone → cap 3 **only when the CRO names the structural mechanism** (which secular_themes.json force, acting how); (b) add the explicit test the prompt currently only gestures at: *a margin/ROIC decline concurrent with a revenue down-cycle that the dossier attributes to demand, not share loss or price, is CYCLICAL — do not apply the cap*; (c) delete the score-cap's echo in the Director prompt (the deterministic `moat_per_name_cap` half-size and the `erosion_severity` eligibility bar stay — code keeps the teeth, the prompt stops pre-crushing the score the Director needs for ranking).
**Impact:** recovers legitimate 4-5 value_convictions in the cyclical-dip cohort — the exact profile (below-SoP fear-print) the conviction-ceiling memo says a 5 requires. Moderate: affects maybe 10-20% of the value pool. **Effort:** S. **Risk:** one more true value trap scores 4 — mitigated by skeptic + deterministic size caps remaining fully intact.

### P4. [SAFETY] Delete the Skeptic's numeric `value_conviction_cap` (verdict-only skeptic).
**Change:** Remove the field from both skeptic workflow generators (`weekly_opus_refresh.py:1283-1284, 1332-1333`), from `consume_skeptic`'s stamping (`_post_common.py:56-57`, default param), and from the publish payload (`publish_to_frontend.py:247`). The skeptic emits verdict + kill_fact + corrections + evidence, nothing else.
**Impact:** closes the proven skeptic-as-cap bug's residual surface (a populated-but-unenforced field is a re-introduction magnet), removes a dishonest UI field, and stops the skeptic anchoring on a number. Pure deletion. **Effort:** S. **Risk:** none — nothing consumes it numerically today (verified: no `min(...cap)` anywhere in backend).

### P5. [SAFETY] Uniform freshness + peer-anchor injection on every non-weekly debate path.
**Change:** Make the ad-hoc/online lanes (`_adhoc_debate.js` generator, `publish_adhoc.py` inputs, any `debate_candidate` call) route through the same prep contract as the weekly path: `metrics_str` MUST include `_ttm_block` (it does when FMP key present — make its absence a logged WARN, not silence), an as-of date on the analyst-consensus line (:1130-1136, one f-string), and a read of `peer_groups/<sym>.json` when present (nightly `debate_candidate` currently never sees peers).
**Impact:** directly targets the measured 87% CONFIRMED_WITH_CORRECTIONS rate — the single best-evidenced silent-failure channel. Won't reach the weekly path's quality (no web), but removes the known stale-anchor class. **Effort:** S-M. **Risk:** minimal; slightly longer prompts.

### P6. [SPEED] De-duplicate the Interrogator/CRO overlap and stop re-sending the transcript to the Moderator on the nightly path.
**Change:** Drop Interrogator §5 (its content is the CRO's `consensus_delta` job) and reduce §8 to the machine tag line + one paragraph (the CRO already re-derives moat/secular fields and the deterministic `_moat_features` is the third read that actually gates). On the nightly path, replace the Moderator's full 18k `t_content` (:1365) with the Q&A tail slice only (the dossier carries the quoted evidence; keep the Architect's full copy).
**Impact:** ~20-30% token cut on the two most expensive calls (~$0.4-0.7/name on the nightly path, meaningful×160; faster weekly resume cycles), and one moat read per layer instead of two contradictable ones. **Effort:** S. **Risk:** the Moderator loses direct access to prepared remarks — acceptable because its evidence-discipline block already forbids citing what it wasn't given, and the dossier + metrics carry the load; revert if catalyst_status quality drops.

### P7. [SAFETY] Move the dated ticker examples out of the durable Director prompts into a generated weekly block.
**Change:** Strip BRBR/CALM/THC+UHS/CMCSA+SAX.DE/PLX.PA-Edenred/ARDT/SREN.SW from `VALUE_DIRECTOR_PROMPT` (:569-571), keeping one *generic* worked example per rule. `value_input()` already appends prior-run measured correlations (:766-778) — extend that generated section to also emit "this pool's live clusters to check" from the actual candidate list (secular_theme counts + flagged pairs), which is strictly fresher than the hard-coded list.
**Impact:** removes stale-anchor contamination of every future value-Director run (wrong-name callouts, dated multiples) — a slow silent-quality leak rather than an alpha unlock. **Effort:** M. **Risk:** generated examples are less vivid than the hand-written ones; keep the prose rules, generate only the names.

### P8. [SPEED] Skeptic pass for the borderline band, funded by P6's savings.
**Change:** Extend the finalist-only skeptic to the *near-miss band* (Director runner-ups + any name within 1 conviction point of the apex cut), reusing the existing workflow generator with a longer SYMS list; keep BATCH=8.
**Impact:** the only seats that currently change hands without adversarial review are exactly the swap candidates the rotation discipline reaches for; ~10 extra agents/week closes that. Modest but real safety-of-selection gain. **Effort:** S. **Risk:** longer weekly wall-clock (one extra batch); do it only if P6 lands first.

## 4. IF YOU ONLY DO ONE THING

**P1 — decouple conviction from the verdict letter and re-gate on `verdict OR value_conviction`.** The proven 0/407 ceiling is treated as a funnel-composition fact (correct), but the rubric at `live_debate_engine.py:783-788` makes it *definitional*: conviction is a timing verdict wearing a confidence costume, and both downstream gates key off it. Every other proposal tunes the machine; this one makes its primary output mean what every consumer already assumes it means — and it is the prerequisite for ever measuring whether the debate's confidence is calibrated at all. (If P1 is deferred, do P2 the same day regardless — it is a two-token change that prevents a guaranteed crash.)
