## 1. WHAT WORKS (keep)

1. **Deterministic, fail-loud funnel with anti-shrink guards.** `disruptor_universe()` re-screens FMP from scratch every run and never reads a prior universe (:1536); hard STOPs on `raw_total < 100` (:1586-1588) and `debated < 25` (:1801-1804), plus the zero-member-theme note (:1808-1811). Silent universe shrink is a proven failure mode elsewhere in this repo (shrink-loop fix in the regime book) — these guards earn their lines.
2. **Hard profitability gates before any narrative.** TTM-FCF-positive-or-inflecting + rev growth ≥15%/accelerating + funded-solvency ≠ weak (:1606-1682). This is what keeps the space theme honestly at 1 member instead of forcing pre-FCF moonshots through (taxonomy note :82) — the gate does real work and the "empty theme is an acceptable outcome" posture is the right epistemics.
3. **The disruption-vector sign gate** (`DISRUPTOR_DIRECTOR_PROMPT` :583-586). This is the genuinely novel content of the book: "abnormal cheapness is a warning, not a margin of safety" + presumptive-disruptee via `victim_layers` cross-check against `secular_themes.json`. It is a real inversion of the value rubric, not a re-skin — and it is the strongest single argument that the disruptor debate framing differs enough from regime/value to justify a separate debate. Keep it verbatim.
4. **Valuation-as-guard, not score driver** (pillar 4, :592) with the explicit `sop_mos_pct ≤ −40% ⇒ veto/half-size` rail. Correct polarity for a momentum-adjacent book; prevents the value-book reflex from importing fake safety.
5. **Deterministic post-processing that never changes membership** (`_disruptor_post.py` design principle P1, :6-7): theme-cap backstop (:176-206), measured 2y weekly correlation + SMH/QQQ theme betas (:311-339 — the right benchmarks for this book, replacing XLY), market-based stress with the bear-case-invalid check (:254-284), idempotent `--offline` re-runs. The measured-corr feed-forward into the next Director prompt (weekly_opus_refresh.py :2226-2233, "argue AGAINST these real numbers") is a cheap, honest anti-hand-waving device.
6. **28-day debate cache + explicit re-debate triggers** (`_disruptor_redebate_triggers` :1826-1899: age, earnings-since, |move|≥15%, thesis-break, new entrant) with the selective self-clean (:1935-1946). This is the main cost control and it is correctly conservative (fail toward re-debate).
7. **NAV isolation is clean.** Separate chained-NAV state files, "NEVER blended" (:2345-2349), the honest highest-vol banner with pool stats (:2414-2420), off-scan price-coverage check before writing (:2360-2364). Sizing floor/clamp (0.1–1.5, default 1.0) in `build_weights` (:146-172) is sane.
8. **Monthly cadence enforced by a self-gate, not a calendar.** `disruptor_prep` hard-stops if `universe.json` is >21d old (:1915-1928). The universe was built 2026-06-10, so the gate fires on the next weekly run — the cadence mechanism demonstrably works (it cannot be silently skipped).

## 2. WEAKNESSES / RISKS

### W1 [PROVEN] — The funnel reproduces the conviction ceiling: it selects consensus, then is surprised the debate returns consensus grades.
Evidence: the Stage-D pre-rank (`prerank`, weekly_opus_refresh.py :1758-1760) sorts by `-load_bearing_score, -rev_cagr_3y, -fcf_margin`. Maximum load-bearing chokepoint = maximum consensus mega-cap: the resulting apex is TSM, NVDA, V, IDXX, BSX (~61% of weight in names every large-cap growth fund already owns). Debate outcome over the 40-name pool: **0 verdict-A, 0 conviction-5, modal conviction 3** — the exact ceiling signature already proven on the 407-name priced-quality funnel, vs 10 A / 6 c5 on the B13 catalyst funnel. Same stack, same composition disease. Failure it causes: the book converges to a QQQ/SMH-lite with an Opus-priced label; 2 of 8 seats (V, IDXX, 21.5% combined weight) are self-stamped `meets_goal=false` in a book whose stated goal is +30-50%/12mo (`RETURN GOAL` :574) — a fifth of the book concedes on entry it can't do the job.

### W2 [PROVEN] — The highest-volatility sleeve is the only book with no independent skeptic kill-tier.
Evidence: `value_skeptic()` (:1250) and `regime_skeptic()` (:1301) exist and REFUTED-demotes (verdict-based, `_value_post.py consume_skeptic` :100-156 — correctly NOT numeric-cap, so the skeptic-as-cap bug is not live here); there is **no `disruptor_skeptic`** anywhere, and the debate template runs Interrogator+Architect+CRO as ONE agent per name (:2546 "You run the COMPLETE multi-agent debate…"). Self-debate has no adversary: the GDOT case (CRO said A/5, independent Skeptic REFUTED on thin arb) proves the kill-tier catches exactly what a single self-grading agent misses. Failure: a theme-narrative fabrication (fake backlog, relabeled cyclical) survives into the sleeve with 2x-value-book drawdowns. The Director's `hype_flag` is graded by the same model that seated the name.

### W3 [PROVEN] — `ev_gp`, the valuation guard's primary input, is silently wrong or missing for a large slice of the pool.
Evidence: weekly_opus_refresh.py :2150-2157 —
```python
ndebt = (s.get("net_debt") if isinstance(s.get("net_debt"), (int, float))
         else (ndE * (ttm_rev) if False else None))
```
The fallback branch is dead code (`if False`), and even if enabled would be dimensionally wrong (debt/EBITDA × revenue ≠ net debt). So for every off-scan name (the disruptor universe barely overlaps the scan by design) EV ≈ market cap: levered names get an optimistically LOW ev_gp. Additionally `gm` for off-scan names falls to a theme_map field that is never emitted by the Sonnet map prompt (:1704-1712 doesn't ask for gross_margin) → **9/40 rows have ev_gp = null** (measured), and `mcap` prefers the up-to-28d-stale universe value over the live scan (:2144 `u.get("mcap") or s.get("market_cap")`). Failure: the pillar-4 guard (the only valuation defense in a rich-screening theme book) is quietly strongest on exactly the names where it has the worst data, and the Director can't tell a null from a pass.

### W4 [PROVEN] — Entry timing exists in prose, not in the NAV: momentum names are filled at publish-day price.
Evidence: `entry_posture` ("wait_for_weakness" / "on_confirmation" / scale_in) is stamped (`stamp_entry_posture`, `_disruptor_post.py` :209-227) and `entry_plan` tranching text (:230-236) — but `_update_apex_tracking` (live_debate_engine.py :2109+) anchors every position at the current price on publish day; there is no PENDING_LIMIT mechanism, though one already exists and is proven honest in B13. The scale-out re-grade proved the whole AI-infra theme screens rich; buying the ramp at the publish print is systematically the worst fill this book can get. Corroborating churn: VRT entered 06-14, closed 06-15 at 0.0%; INTU closed −3.52% after 5 days (both pre-rotation-ledger, but the fills were real). Failure: the tracked NAV structurally embeds buy-after-the-run slippage, then the track record is used to judge the methodology.

### W5 [PROVEN in code / SUSPECTED in magnitude] — Theme caps count taxonomy LABELS, not the shared hyperscaler-capex factor.
Evidence: `enforce_theme_caps` (`_disruptor_post.py` :176-206) buckets by `themes[]` strings. CCJ is counted only under energy_transition, yet its measured SMH beta is 0.66 (live artifact) and the taxonomy itself warns about the data-center-power overlap (disruptor_themes.json :27). Label exposure says ai_infrastructure = 27.5% (< 30% cap, compliant); factor exposure TSM+NVDA+CCJ ≈ 41% on the one hyperscaler-capex line. The corr breach cap needs corr ≥ 0.7 AND combined weight > 16% (:311-323) — TSM-NVDA at 0.63/27.5% sails under it. Partial mitigation, honestly noted: measured avg pairwise corr is 0.24 and the non-AI half of the book has QQQ betas 0.37-0.83, so this is NOT one-factor-in-costumes across all 8 — the concentration is specifically the AI-capex sleeve leaking past a label-based cap.

### W6 [SUSPECTED] — Director cap-compliance is cosmetic where it matters.
Evidence: the one Director-authored `combined_cap` is `{NVDA,TSM, max_units 2.05, axis ai-capex}` — exactly the current sum of their units (1.0 + 1.05). A cap set at the current value binds nothing; it satisfies the prompt's "keep both ONLY with an explicit combined-size cap" (:600) as pure paperwork. Same family: emitted size_units span only 0.75–1.05, so an 11-point disruptor_score spread (73→84) compresses to a 4pp weight spread — conviction is decorative in the weights.

### W7 [SUSPECTED] — Taxonomy is static and carries dead weight; the monthly rebuild adds a whole extra Workflow cycle to an already multi-hour run.
Evidence: `disruptor_themes.json` version 1.0, updated 2026-06-10, no add/retire mechanism; by_theme debate slots: space=1 member ever, genomics=4, defense_tech debated 8 and seated 0 in both graded runs. Every debated-but-never-seatable name is a full single-agent Opus web debate (~8 defense names/run). Meanwhile plausible 2026 themes (AI application-layer monetizers, GLP-1 supply chain, grid-storage software) have no path in except a manual taxonomy edit. Failure: spend without seats + slow taxonomy rot, on a book whose whole premise is theme freshness.

### W8 [SUSPECTED, ops] — Fragile cache-age plumbing and a hair-trigger re-debate rule on a high-vol book.
Evidence: debate age = **file mtime** (:1874-1879) — any git operation/copy that touches `disruptor/results/*.json` silently resets or inflates ages (the repo is a shared working dir with a second session committing; mtimes are not stable there). And |move|≥15% (:1891-1893) fires routinely on this sleeve's names (TOST/CCJ class), so weekly re-debate counts will drift toward full-universe cost in volatile tapes. Failure mode is cost + the multi-resume ops pain, not correctness.

Minor (noted, not proposal-worthy): `expected_return_pct` falls back to `sop_mos_pct` at publish (:2433-2434) even though the rubric explicitly says MoS is not a return forecast in this book — display-level inconsistency. `why[sym]` dead conditional at :1865-1867 (`"no-cache" if not m.get("held") else "no-cache"`) — both branches identical, the intended new-entrant label is unreachable.

## 3. PROPOSALS (ranked)

### P1 [RETURN] — Reserve pre-rank debate slots for the un-priced part of the S-curve. **← the one that attacks the proven bottleneck**
Change: in `disruptor_map_merge()` Stage D (:1757-1771), split the ≤8/theme cut into 5 consensus slots (current `prerank`) + 3 reserved slots filled by the best names with `s_curve_stage ∈ {early_adoption, steep_ramp}` AND mcap below ~$25B (both fields already exist per name), ranked by the same key. Optionally add `mcap` as a mild penalty term in `prerank` for the reserved lane. No new agents, no new data.
Why: the empirical record says the return bottleneck is FUNNEL COMPOSITION — the B13 funnel produced 10 A / 6 c5 from 17 names while this 40-name consensus pool produced 0/0 with modal conviction 3. The debate machinery is fine; it is being fed names on which no informed disagreement is possible. Expected impact: honest magnitude — this does not manufacture alpha, it creates the *possibility* of a 4/5-conviction seat; expect 1-2 genuinely differentiated seats per quarter, not a transformed book. Effort: **S**. Risk: smaller names = thinner data (more online-fetch debates), higher single-name vol; the profitability hard gates (:1648-1653) already bound the junk risk.

### P2 [SAFETY] — Add a disruptor skeptic kill-tier (verdict-based demotion only).
Change: clone `value_skeptic()` (:1250-1298) → `disruptor_skeptic()` over the ~13 finalists (apex + runner_ups), writing `disruptor/_skeptic/<SYM>.json`; consume it in `_disruptor_post.py` with the `_post_common` REFUTED→demote pattern (`_value_post.py` :100-156). Explicitly do NOT consume `value_conviction_cap` numerically — the skeptic-as-cap bug is proven; verdict-based demotion only (REFUTED→kill, CORRECTIONS→note, CONFIRMED→none). Insert into `run_speculair_weekly.ps1` STEP 3C.
Why: the highest-drawdown sleeve is the only book where one agent grades its own homework (:2546); the kill-tier is the single most-proven piece of teeth in the stack (GDOT). Expected impact: prevents ~1 narrative-fabrication seat per quarter — low frequency, high severity. Effort: **S** (it is a parameterized clone; the consume pattern is shared). Risk: +13 web-heavy Opus agents/weekly run (batch ≤6 per the rate-limit evidence); a default-REFUTED skeptic may over-kill momentum names whose "load-bearing facts" are guidance, not filings — tune the disruptor skeptic's primary-source bar to accept dated earnings-call guidance.

### P3 [SAFETY] — Publish a beta-matched benchmark line next to the disruptor NAV.
Change: in `disruptor_publish()` (:2345), compute a benchmark return from the already-measured `theme_beta` (weights' weighted-average SMH/QQQ betas → a b_smh·SMH + b_qqq·QQQ daily blend, or simpler: track SMH and QQQ NAVs from the same inception in the same tracking file) and emit `active_return_pct` in the payload + banner.
Why: the book's entire justification is "additive vs a beta basket"; today nothing measures it, and the current composition (61% consensus mega-caps) makes "closet SMH/QQQ" the null hypothesis. Per the per-record-detail memory rule, show it per-position too (each name vs its own beta-scaled benchmark). Expected impact: zero alpha, total honesty — this is the instrument that decides in ~2 quarters whether the sleeve deserves to exist. Effort: **S-M** (extend `_update_apex_tracking` or a sidecar; watch the GCS read-modify-write staleness gotcha — pin generations). Risk: the number is ugly and Bruno has to act on it. That is the point.

### P4 [SAFETY] — Fix the `ev_gp` construction (delete the dead branch, use the funded-leverage data you already have).
Change: weekly_opus_refresh.py :2150-2157 — remove the `if False` dead expression; for off-scan names take net debt from the `_funded_leverage` cache (it already fetched balance-sheet data for `ndE`; expose `net_funded_debt` absolute alongside the ratio) and gross margin from the Stage-B income-statement fetch (`gates_for` already pulls quarterly income statements at :1636 — one field away). Emit `ev_gp_basis:"full"|"mcap_only"|null` so the Director sees degraded inputs as degraded.
Why: 9/40 null + EV≈mcap for the levered rest silently guts pillar 4 — the only valuation defense in a book whose theme screens rich. Expected impact: correctness of an existing control, no new alpha. Effort: **S**. Risk: essentially none; touch only `disruptor_input()`.

### P5 [RETURN/SAFETY] — Make `entry_posture` real in the NAV, or delete it.
Change (preferred, honest-tracking form): for picks stamped `wait_for_weakness` or `on_confirmation`, enter the tracker as PENDING_LIMIT at the Director's stated add-level (derive: wait_for_weakness → e.g. min(publish px −7%, 20d low); on_confirmation → fill at the event-day close), exactly the B13 fill discipline (append-only, no fiction fills). Why: the scale-out evidence says the theme screens rich; publish-day fills on momentum names systematically buy the top of the week. Expected impact: modest but real — on a 8-name book a 3-5% better average fill on 2-3 reach names/quarter is ~1pp/quarter of NAV; equally important, it stops the track record from lying about executable entries. Effort: **M**. Risk: limit-never-fills bias (a runner you never board looks like a miss, not a save) — log unfilled limits explicitly so the counterfactual is visible.

### P6 [SPEED] — De-duplicate Opus debates against the scale-out overlay, and stop debating perennially seatless themes.

Expected impact: ~25-35% fewer disruptor debate agents/run → one fewer resume cycle in the multi-hour weekly, materially less rate-limit exposure. Effort: **M**. Risk: framing mismatch when reusing scale-out output (its rubric is scale-tier, not disruptor) — reuse the verified FACTS, not the verdict; a watch-listed theme inflects and the book is a month late (acceptable: the monthly universe still screens it and the guard prints it).

### P7 [SAFETY] — Count measured AI-capex beta toward the theme cap, not just the label.
Change: in `_disruptor_post.py`, after `corr_block`, fold any pick with SMH beta ≥ ~0.6 into the ai_infrastructure bucket for `enforce_theme_caps` purposes (a shadow membership: `themes_effective`), so the 30%-per-theme deterministic backstop measures the factor, not the taxonomy string. Risk: beta noise on 2y weekly windows (≥60 obs required already, acceptable); a genuinely orthogonal name with incidental SMH co-movement gets clipped — the cap scales, it doesn't evict.
