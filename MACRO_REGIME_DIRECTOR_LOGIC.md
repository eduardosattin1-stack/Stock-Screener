# Macro Regime → Director Decisions

**What this doc is:** a code-level walkthrough of the macro regime classifier
(`backend/macro_regime.py`) and an honest map of how — and how much — its output actually
moves the Director agents that seat capital.

**Status:** descriptive, not aspirational. Where a piece of the wiring exists but is not
connected, this doc says so (see [§9 Known gaps](#9-known-gaps--dead-wiring)).

---

## 0 — TL;DR

1. `macro_regime.py` turns 5 (v7) or 9 (v8) macro time-series into one composite score
   `0.0–1.0`, and cuts that score into four **risk-axis regimes**:
   `RISK_ON | NEUTRAL | CAUTIOUS | RISK_OFF`.
2. It *separately* re-reads two of its own sub-scores (growth × inflation) into a
   **JPM-style 2×2 quadrant**: `GOLDILOCKS | REFLATION | STAGFLATION | RISK_OFF`.
   The quadrant, not the risk label, is what the Apex Director keys off.
3. The weekly Opus pipeline snapshots that into `backend/_opus_debate/macro_regime.json`.
   The **Apex Director** and **Disruptor Director** read that file and translate the
   quadrant into one output field — `risk_stance` (`aggressive|balanced|defensive`) — plus
   a per-pick `regime_fit` note.
4. Macro is a **tilt on an already-gated set, never a gate itself.** Nothing is admitted or
   excluded because of the regime. Eligibility comes from conviction ≥ 3, the numeric gate,
   the skeptic verdict and the lane rules; sizing comes from the conviction band and the
   correlation/theme caps. Macro shapes *what kind* of name wins a seat and how hard the
   Director reaches for return — not *whether* a name is allowed to compete.
5. The **Speculair live director** (`live_director_agent.py`) does **not** read the
   classifier at all. Its "macro brief" is prose generated by a separate LLM call. See §6.2.

## 1 — Two different things called "regime"

They are unrelated and are easy to confuse in this repo:

| | **Macro regime** (this doc) | **Catalyst regime** |
|---|---|---|
| Artifact | `backend/macro_regime.py` → `backend/_opus_debate/macro_regime.json` | `CATALYST_WATCH_REGIME.md` |
| Nature | Deterministic classifier over market/economic data | Hand-authored, agent-researched living document |
| Cadence | Every weekly pipeline run | Regenerated bi-weekly/monthly, manual |
| Answers | "Is the macro backdrop risk-on, and is it growth-up or inflation-hot?" | "Is the M&A / spinoff / distressed *lane* open right now?" |
| Consumed by | Apex Director, Disruptor Director, RegimeRead agent, frontend pulse | Apex Director (STEP 1), Catalyst Watch scoring |

The Apex Director prompt reads **both** in its STEP 1. This doc covers the first.

## 2 — The classifier: inputs → sub-scores

Every sub-score is normalised so that **higher = more risk-on**, `0.0–1.0`. All thresholds
are hand-tuned step functions (explicitly labelled "hand-tuned priors; ML will optimize"),
not fitted parameters.

### v7 — 5 signals (`_compute_regime`)

| Sub-score | Source | Logic | Weight |
|---|---|---|---|
| `yield_curve` | Treasury 10y − 2y | ≥150bp → 1.0; flat (0bp) → 0.35; < −50bp → 0.0 | 0.25 |
| `vix` | VIX spot + 200d SMA | 60% absolute level (≤12 → 1.0, >40 → 0.0), 40% VIX/SMA200 ratio | 0.25 |
| `cpi_trend` | CPI, ~9mo history | 3-month annualised rate, level-scored, then **×0.7 if accelerating** vs the 6-month rate | 0.20 |
| `yield_level` | Treasury 3m (FFR proxy) | ≤2% → 1.0; >6% → 0.0 | 0.15 |
| `gdp_momentum` | GDP, ~4 quarters | QoQ growth banded, **+0.10 if accelerating** | 0.15 |

### v8 — 9 signals (`_compute_regime_v8`, `SUB_WEIGHTS_V8`)

v8 keeps all five and adds four recession-sensitive inputs, drawing 0.35 of weight off the
originals:

| Added sub-score | Source | Weight | Note |
|---|---|---|---|
| `yield_curve_3m` | 10y − 3m spread | 0.10 | NY-Fed recession indicator (Estrella & Mishkin) |
| `unemployment` | `unemploymentRate` | 0.10 | Level + 3-month delta; ≥0.6pp rise = Sahm-rule penalty |
| `recession_prob` | `smoothedUSRecessionProbabilities` | 0.08 | Inverted and compressed; deliberately down-weighted because it is structurally the most risk-off signal in the set |
| `consumer_sentiment` | UMich `consumerSentiment` | 0.07 | Level + 3-month % change |

Re-weighted originals: `yield_curve` 0.15, `vix` 0.18, `cpi_trend` 0.12, `yield_level` 0.10,
`gdp_momentum` 0.10. An `assert` enforces the sum to 1.0 at import time.

Both versions ship live; **which one runs depends on the caller** (§6).

## 3 — Composite → regime label

```python
macro_score = Σ(sub_score × weight)          # 0.0 – 1.0

classify_regime(macro_score):
    ≥ 0.65 → RISK_ON
    ≥ 0.45 → NEUTRAL
    ≥ 0.30 → CAUTIOUS
    < 0.30 → RISK_OFF
```

Two structural consequences worth knowing before you read a regime label:

- **NEUTRAL is a wide, sticky band (0.45–0.65).** Because sub-scores are averaged step
  functions, extremes cancel: a deeply inverted curve (0.0) plus a calm VIX (0.85) lands
  mid-band. Expect the label to sit on NEUTRAL through a lot of genuinely different tape.
  The current snapshot is `NEUTRAL @ 0.5475`.
- **It is a single risk axis.** That is exactly why the quadrant in §4 was added.

## 4 — The growth × inflation quadrant (the part the Director actually uses)

`growth_inflation_quadrant()` (added 2026-07-16, after JPM's agentic-regime work) re-reads
the classifier's own two macro-fundamental sub-scores instead of collapsing them onto the
risk axis:

```
                     inflation COOLING (cpi_trend ≥ 0.5)   inflation HOT/STICKY (< 0.5)
growth UP   (gdp ≥ 0.5)        GOLDILOCKS                        REFLATION
growth DOWN (gdp <  0.5)       RISK_OFF                          STAGFLATION
```

The rationale in the docstring is the key insight: the single risk label **cannot
distinguish STAGFLATION from a disinflationary RISK_OFF slowdown** — both read "risk-off",
but one wants pricing power and real assets while the other wants quality and duration.
Both axes were always measured; the quadrant just stops discarding one of them.

`quadrant_basis` carries the raw sub-scores as prose (e.g. `growth up (gdp 0.65) × inflation
hot/sticky (cpi 0.42)`), so a mid-band read stays auditable rather than hiding behind a label.

Note: `growth_inflation_quadrant` is spliced into the **v7** return dict only. `_compute_regime_v8`
does not emit `quadrant` or `regime_detail` (see §9).

## 5 — The classifier's output contract

`fetch_macro_regime()` (v7) returns:

```jsonc
{
  "regime": "NEUTRAL",              // risk axis
  "score": 0.5475,
  "sub_scores": { "yield_curve": …, "vix": …, "cpi_trend": …, … },
  "regime_detail": {                // quantitative → English, for LLM prompts
    "growth":    "accelerating | stable | decelerating",
    "inflation": "decelerating | sticky | accelerating",
    "rates":     "accommodative | neutral | restrictive",
    "credit":    "complacent | stable | fearful"
  },
  "quadrant": "GOLDILOCKS | REFLATION | STAGFLATION | RISK_OFF",
  "quadrant_basis": "growth up (gdp 0.65) × inflation hot/sticky (cpi 0.42)",
  "features": { "macro_regime_score": …, "macro_vix": …, … },   // ML/backtest features
  "tilts":  { … },                  // factor-weight multipliers — see §9
  "rates":  { … }                   // raw treasury row
}
```

`regime_detail` exists purely to hand an LLM English instead of decimals — the comment in
the code says so: *"Map quantitative sub-scores to explicit English labels to feed directly
into the AI Persona JSON input."* That is the bridge from the quant layer to the Director.

### Data resilience

- **VIX** prefers the Massive API (`I:VIX` price + 200d SMA), falls back to FMP `quote ^VIX`.
- **CPI / GDP / unemployment / sentiment / recession-prob** are fetched from FMP
  `economic-indicators`, then written to a **GCS last-known-good cache**
  (`gs://screener-signals-carbonbridge/macro/last_known_good.json`). On an empty FMP
  response the cache is read back; only if *both* fail does a hardcoded seed apply. This
  matters because a silent FMP outage would otherwise default every sub-score to 0.50 and
  quietly manufacture a NEUTRAL regime.
- **Backtest mode** (`fetch_macro_regime_historical`, `fetch_macro_regime_v8_historical`)
  applies **publication-lag guards** so a date-`D` backtest only sees series that would
  actually have been released by `D`: unemployment +7d, sentiment +14d, recession-prob +35d,
  CPI +14d, GDP +30d. This is the look-ahead defence for ML/backtest features.

## 6 — Who consumes it

There are four consumers, and they are **not** equally wired.

### 6.1 Weekly Opus pipeline → the Apex & Disruptor Directors ← *the real path*

```
weekly_opus_refresh._write_macro_regime()        # calls fetch_macro_regime (v7)
        ↓
backend/_opus_debate/macro_regime.json           # {regime, score, regime_detail,
        ↓                                        #  quadrant, quadrant_basis, features, asof}
   ├── RegimeRead agent  → regime_read.json      # adversarial second opinion
   ├── Apex Director     → apex_basket_opus_regime.json
   └── Disruptor Director→ disruptor basket
        ↓
_regime_post.py (deterministic post layer) → publish_to_frontend.py → UI + _regime_ledger.jsonl
```

`_write_macro_regime()` runs in the pipeline's setup phase, before the debates, with the
comment *"macro read for the Director's risk_stance"*. It fails soft: a hard failure writes
`{"regime": "NEUTRAL", "score": 0.5, "fallback": true}` rather than wedging the run.

### 6.2 Speculair live debate engine → `live_director_agent.py` ← *not the classifier*

`live_debate_engine.run_macro_strategist()` builds the `macro_brief` the live Director sees.
It is a **`claude-opus-5` call with no macro data attached** — only today's date and the
sector histogram of the debated candidate pool. Its own docstring is explicit:

> *"NOTE: reflects the model's macro knowledge; wiring a live rates/inflation/breadth data
> feed is a planned enhancement."*

So the string that lands under `=== MACRO REGIME BRIEF ===` in the live Director prompt is
model-recall prose, **not** `macro_regime.py` output. The Director prompt's step 4 ("MACRO &
SECTOR FIT — use the macro brief and sector momentum as a tailwind/headwind overlay; do not
cluster the basket on a single macro bet") is therefore acting on that prose. This is the
single largest gap between the two Director families. The brief is also built only when the
Director actually re-runs — at most every `DIRECTOR_CADENCE_DAYS = 30`, or on a held-name
earnings event.

### 6.3 `screener_v6.py` → display only

The scan calls `fetch_macro_regime_v8(fmp)` once at scan-end and returns it as `macro_data`
for the frontend ribbon. Failure is explicitly non-fatal. It does **not** feed selection —
see §9 on `apply_macro_tilt`.

### 6.4 `run_server.py /macro` → frontend pulse

Serves a lean v8 payload (`regime`, `score`, `sub_scores`, `features`), 5-minute cache. The
briefing's quadrant chip does **not** come from here — `/macro` (v8) carries no
`regime_detail`, so `frontend/app/api/briefing/route.ts` reads `spec.macro_regime`, the v7
snapshot published with the baskets, and derives a label-based quadrant fallback if the
published `quadrant` is missing or `UNKNOWN`.

## 7 — How the Director actually turns a quadrant into decisions

### 7.1 The quadrant playbook (Apex Director, STEP 1)

The Director's mandate is `+30–50% over ~12 months` (`RETURN_GOAL`). The quadrant decides
**how hard it is allowed to reach for that**, and **which kind of asymmetry** counts:

| Quadrant | Stance | What the Director is told to do |
|---|---|---|
| **GOLDILOCKS** | reach | Pursue the goal via credible 12-month re-rate drivers — dated catalyst, earnings inflection, live trend. Accept more demand-cycle / AI-capex beta. |
| **REFLATION** | rotate | Favour **pricing power, cyclical value, real-asset re-rates** over duration-sensitive growth — inflation eats long-duration multiples. |
| **STAGFLATION** | defend the reach | Pricing power + real assets **only** on the reach side. Size down demand-cycle beta and duration. Favour carry. |
| **RISK_OFF** (disinflationary slowdown) | defend | Quality, balance sheet, FCF carry, structural floors — *even if `+30–50%` becomes an 18–24-month story.* |

That last clause is the load-bearing one: the macro read is allowed to **stretch the
horizon** rather than force the book to chase the number into a slowdown.

The Disruptor Director runs a coarser two-state version off the same file (`RISK_ON /
accelerating-growth → REACH`, `RISK_OFF / decelerating / sticky-inflation → DEFEND`, size
down the high-beta reaches) — it reads `regime`, `score` and the growth/inflation/rates/credit
detail, and does not use the quadrant.

### 7.2 What the macro read is required to produce

The Director must emit, in `apex_basket_opus_regime.json`:

- `risk_stance` — `"aggressive" | "balanced" | "defensive"`
- `regime_quadrant` — echo of the quadrant it applied (so the call is auditable, not implied)
- `macro_read` — one sentence tying `macro_regime.json` + the regime read + the return goal
- per pick: `regime_fit` — how *that seat* sits in *this* regime

`regime_fit` is the only per-name macro field. It is rendered on the UI (appended to the
rationale as `· Regime: …`) and is listed in the Director's selection levers **after** the
primary ones: *"Select using sop_fair_value / risk_reward / catalyst_status AS PRIMARY
LEVERS … **then** regime fit and consensus-delta width."* Macro is an explicit tiebreak, not
a first-order screen.

### 7.3 The adversarial layer: RegimeRead

Before the Director runs, a separate agent reads `macro_regime.json` and tries to break it:

1. State the quadrant per the dials and what it implies for a 12-month book.
2. **Argue against the dials** — hunt for macro prints from the last 3 weeks that contradict
   them (CPI/PCE, payrolls, PMIs, credit spreads, 10y moves), every claim dated.
3. Emit 2–4 dated **falsifiers** with `check_by` dates — checkable conditions that would flip
   the quadrant call, scored by the *next* run.

It writes `regime_read.json` with `agent_view: AGREE | CONTRADICT`, evidence, falsifiers,
`stance_note` and `confidence`.

**The authority rule is explicit and asymmetric:**

> *"the DIALS are authoritative; a CONTRADICT with dated evidence may temper your stance
> ONE notch, never flip the dial."*

So an agent that disagrees can move `aggressive → balanced`, never `aggressive → defensive`,
and can never change the quadrant itself. The Director must carry the falsifiers into its
memo so the following week can score them.

### 7.4 The regime call keeps a track record

Every publish appends one row to `backend/_opus_debate/_regime_ledger.jsonl`: date, regime,
score, quadrant + basis, the agent's view/confidence/falsifiers, the `risk_stance` actually
applied, the quadrant the Director echoed, the `macro_read`, and the book's expected return.

The stated purpose: *"so the regime dial earns a live-forward track record like every other
paper book — score quarterly: did defensive stances precede drawdowns? did the agent's
CONTRADICT calls beat the dials? did falsifiers fire?"* The macro layer is on the hook for
its own calls, not just the picks.

### 7.5 Deterministic fallback

If the Director omits `risk_stance`, `publish_to_frontend.py` derives it straight from the
classifier label:

```python
_stance_map = {"RISK_ON": "aggressive", "NEUTRAL": "balanced",
               "CAUTIOUS": "balanced", "RISK_OFF": "defensive"}
baskets["risk_stance"] = director.get("risk_stance") or _stance_map.get(_macro["regime"], "balanced")
```

Note `CAUTIOUS` and `NEUTRAL` both collapse to `balanced` here — the deterministic fallback
is coarser than the four-quadrant playbook the Director itself is given.

## 8 — What macro does *not* do

This is the part most often assumed wrong. Macro is deliberately confined to the *tilt*
layer. It does not touch:

| Layer | Governed by | Macro's role |
|---|---|---|
| **Eligibility** | `conviction ≥ 3` AND `numeric_gate ∉ {REJECT, EXCLUDE_ELIGIBILITY}` | none |
| **Hard kills** | Skeptic `REFUTED` → hard no-seat; `_regime_post.numeric_demote` → forced demotion to runner-ups | none |
| **Book separation** | Basket-13 event-driven names are structurally ineligible for the apex, regardless of regime | none |
| **Position sizing** | `size_units` from the banded conviction rubric, then `build_weights` under per-name / secular-theme / measured-correlation caps | none directly |
| **Conviction drift** | `conviction_clamp` — an unjustified move > ±10 vs the ledger is clamped to prior ± 10 | none |
| **Rotation** | Ledger-based: KEEP unless thesis is *broken*; RE-ADD requires a documented thesis change | none |

Macro enters only where the Director exercises judgement: which of several eligible names
best fits the quadrant, how hard to reach for the return goal, whether the horizon stretches,
and how the correlation stress is framed (STEP 4's mandatory demand-cycle-beta and
European-cyclical-recession stress is a macro-shaped exercise even though it consumes no
macro fields directly).

**In one line:** the classifier chooses the *lens*; the deterministic gates choose the
*universe*; conviction and caps choose the *size*.

## 9 — Known gaps & dead wiring

Documented so nobody assumes a connection that isn't there.

1. **`apply_macro_tilt()` is imported but never called.** `screener_v6.py:221` imports it;
   there is no call site anywhere in the repo outside `macro_regime.py`'s own `__main__`
   demo. The entire `REGIME_TILTS` table — the per-regime factor multipliers (`technical`
   ×0.50 in RISK_OFF, `quality` ×1.60, `insider` ×1.40, …) — is therefore **inert in the
   live screener**. Composite factor weights are not regime-tilted today. The table is still
   returned on the `tilts` key, so it looks live in the payload.
2. **`regime_composite_floor()` is likewise never called.** The documented behaviour
   (RISK_OFF raises the entry composite floor +0.05, RISK_ON lowers it −0.05) is not applied
   anywhere.
3. **The live Speculair Director gets prose, not the classifier** (§6.2). Wiring
   `run_macro_strategist` to consume `macro_regime.json` is the highest-leverage fix in this
   area — it would put both Director families on the same macro evidence.
4. **`_write_macro_regime`'s docstring says "v8" but the code calls v7** (`fetch_macro_regime`).
   This is currently *correct behaviour by accident*: `_compute_regime_v8` emits neither
   `regime_detail` nor `quadrant`, so switching to v8 as written would silently strip the
   quadrant the Apex Director's playbook depends on. Porting `growth_inflation_quadrant`
   and `regime_detail` into `_compute_regime_v8` is a prerequisite for any v8 switch.
5. **Feature-key mismatch in the snapshot.** `_write_macro_regime` copies the keys
   `macro_vix, macro_yield_spread, macro_recession_prob, macro_cpi, macro_unemployment`.
   v7 emits `macro_cpi_score` / `macro_gdp_score` and has no unemployment or
   recession-probability features at all — so three of the five keys never survive the copy.
   The checked-in `macro_regime.json` shows the result: only `macro_vix` and
   `macro_yield_spread`.
6. **The checked-in snapshot predates the quadrant** (`asof: 2026-06-29`, no `quadrant` key).
   The briefing's `quadrantFallback` derives one from `regime_detail` labels until the next
   weekly run overwrites the file.
7. **Thresholds are hand-tuned priors.** Every band in every sub-score, the sub-weights, and
   the four regime cut-points are asserted, not fitted. The code says ML will optimise them;
   it hasn't yet. The `_regime_ledger.jsonl` track record (§7.4) is the mechanism that will
   eventually make that possible.

## 9b — Addendum (2026-07-27): the Dalio debt-cycle axis shipped

The handover spec's third axis is now live, which retires several §9 gaps:

- **`backend/debt_cycle.py`** — `EXPANSION → DISCIPLINE → FORCING → MONETIZATION`,
  6 gauges (real 30y rate, term premium, TreasuryDirect auction quality, interest/receipts,
  HY OAS, Fed balance sheet), path-dependent state machine (2-publish hysteresis, one legal
  step per publish, illegal jumps logged as `transition_blocked`). Convention inverted vs
  this file's classifier: higher sub-score = later in the cycle. Gold is a falsification
  check only, never an input.
- **Authority (FORK 2/B):** the phase modifies the quadrant stance (DISCIPLINE caps at
  `balanced`, FORCING floors at `defensive`, MONETIZATION unlocks `aggressive` even from a
  RISK_OFF quadrant) and caps the aggregate `story` duration-bucket share in
  `_regime_post.enforce_duration_caps`. It still never gates eligibility or moves conviction —
  §8's table stays true, with "sizing: none directly" amended to "aggregate duration caps only."
- **§9.1 partially retired:** the snapshot's feature copy is now whitelist-free with a
  fail-loud check. (`apply_macro_tilt`/`regime_composite_floor` remain dead — wire-or-delete
  still open.)
- **§9.3 retired:** `run_macro_strategist` now injects the classifier snapshot (regime +
  quadrant + phase + falsifiers) into the live Director's macro brief, and a phase transition
  forces a live-Director re-run outside the 30-day cadence.
- **New surfaces:** briefing `CYCLE` chip with dated falsifiers, C/P/S payback badges (✂ when
  the cap trimmed a seat), `_cycle_ledger.jsonl` with the realized duration mix per publish.
- **Ops:** TreasuryDirect auction fetch runs Saturdays 05:00 Amsterdam
  (`python backend/debt_cycle.py fetch-auctions`), before the weekly routine; the classifier
  self-heals a stale cache inline.

## 10 — Quick reference

| Question | Answer |
|---|---|
| Where is the regime computed? | `backend/macro_regime.py` |
| Where is it snapshotted? | `backend/_opus_debate/macro_regime.json`, written by `weekly_opus_refresh._write_macro_regime()` |
| Which version writes that snapshot? | v7 (`fetch_macro_regime`) — the only one that emits `quadrant` + `regime_detail` |
| Which version serves the UI? | v8 (`fetch_macro_regime_v8`) via `run_server.py /macro` and `screener_v6` |
| What does the Director read? | `macro_regime.json` + `regime_read.json` + `CATALYST_WATCH_REGIME.md` |
| What does the Director emit? | `risk_stance`, `regime_quadrant`, `macro_read`, per-pick `regime_fit` |
| Can macro veto a pick? | **No.** Vetoes are skeptic `REFUTED`, numeric gate, eligibility floor, lane rules |
| Can macro size a pick? | **No.** Sizing is `size_units` + conviction bands + theme/correlation caps |
| Can an agent overrule the dials? | One notch of stance, with dated evidence. Never the quadrant |
| Is the regime call scored? | Yes — one row per publish in `_regime_ledger.jsonl`, with falsifiers |
