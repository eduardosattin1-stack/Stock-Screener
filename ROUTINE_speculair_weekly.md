Weekly **all-Opus Speculair refresh**, designed to be fully hands-off. You are running automatically in the Stock-Screener repo at `C:\Users\Bruno\Stock-Screener` with NO memory of prior conversations — everything you need is below and in the repo. Goal: re-debate the entire per-methodology candidate universe with Claude Opus 4.8 (regime-aware), re-pick the apex 10, and publish the updated debates + per-symbol debate HISTORY to production GCS so every stock page + the Speculair tracker show fresh Opus analysis. The debate runs as Claude Code Opus SUBAGENTS on the subscription — no Anthropic/OpenAI API key (only FMP + GCS + web calls use keys/network, already configured).

**Operating rules (Bruno's standing instructions):**
- This pipeline runs ENTIRELY on Claude Code (local). NEVER deploy any of it to Cloud Run / Cloud Run Jobs.
- The frontend is already deployed and reads GCS live, so NO frontend commit/deploy is needed — refreshing GCS data IS the whole job.
- This routine ONLY consumes the production scan's outputs and overlays the Opus debate layer. Do NOT edit `screener_v6.py`, the production scan, or any Cloud Run job.
- All commands below are pre-allowlisted — every `python backend/weekly_opus_refresh.py …` mode (via a wildcard rule), `publish_to_frontend.py --gcs`, `compact_table.py`, and `gcloud storage …` — so a headless run completes without permission prompts. The value-director subagent (STEP 3B) only Reads/Writes local files. If a step's GUARD trips, STOP and report rather than publishing degraded data.
- The DISRUPTOR LENS is RETIRED (2026-07-02, FUTURE_RESOURCES_SPEC.md §10): never run any `disruptor-*` mode — they are code-level no-ops that print a RETIRED notice and exit 0 (`ALLOW_DISRUPTOR=1` is the only override, operator-only).

STEP 0 — REPO SYNC (~30 s; keeps this box's code current — the repo is developed both here and in cloud sessions, and code fixes land on `main` via PRs). Run `git rev-parse --abbrev-ref HEAD` and `git status --porcelain`. ONLY if the branch is `main` AND the tree is clean, run `git pull --ff-only origin main` and report the old→new commit in the STEP 4 summary. In ANY other state — wrong branch, dirty tree, diverged history, a permission prompt on the git command — print `REPO SYNC SKIPPED: <reason> — running with the local copy` and CONTINUE; NEVER stash, reset, force-pull, or switch branches unattended. A skipped sync is never a failure.

STEP 1 — PREP (deterministic, ~3-6 min; fetches FMP transcripts). Run:
`python backend/weekly_opus_refresh.py prep`
It (a) **self-cleans** — archives the prior run's `results_regime/`, `dossiers/`, `apex_basket_opus_regime.json` into `_opus_debate/_archive_prev/` so the Director only ever sees ONE coherent pass; (b) sources the universe from the **RAW 11-methodology production screen** (`scans/methodology_picks.json` on GCS — the full opportunity set, re-read every week; NOT the curated `speculair_baskets.json`, which created a self-shrinking loop), and unions in the current apex (held names); (c) builds per-name input bundles + fetches the latest FMP transcripts; (d) for names with NO FMP transcript, marks them for **ONLINE fetch** instead of skipping; (e) emits a self-contained debate workflow with both name-lists baked in. It prints two key lines:
  `raw screen methodology_picks.json: last_updated=... methodologies=<M>`
  `PREP OK: <fmp> with FMP transcripts + <online> via online fetch = <TOTAL> total candidates (online: [...])` and `WORKFLOW_SCRIPT=<absolute path>`.
CHANGE-DETECTION (2026-07-01): most unchanged names are now CARRIED FORWARD (prior debate restamped with live price + as_of + `carried=true`) instead of re-debated — a name re-debates only on: new transcript / >10% price move / prior catalyst PENDING_HARD / seat-relevant (apex+runner in any book, ALWAYS) / record >21d old / new to the universe. Expect ~45-70 debates instead of ~149; earnings weeks spike back up by design. `FORCE_FULL_DEBATE=1` env overrides the gate.
GUARD: if `COVERED < 30` (debated + carried, the last number on the PREP OK line), the printed `methodologies=<M>` is `< 8`, or the WORKFLOW_SCRIPT path is missing → STOP and report a degraded screen (cf. the 2026-06-06 incident: 8 methodologies / 15 names). A healthy run COVERS ~45-150 across 11+ methodologies; the DEBATED subset alone may legitimately be small on a quiet week.

If it prints `no non-binary B13 equity special-sits` → SKIP this step. Otherwise invoke the Workflow tool: `Workflow({ scriptPath: "<the WORKFLOW_SCRIPT path>" })` (Interrogator → Architect → CRO + Skeptic + Director, catalyst-framed, batched ≤6). STEP 2 — DEBATE + DIRECTOR (Opus subagents, ~30-60 min). Invoke the Workflow tool: `Workflow({ scriptPath: "<the WORKFLOW_SCRIPT path from Step 1>" })`. Every candidate runs a single-agent full Opus regime debate (Interrogator → Architect → Moderator, applying CATALYST_WATCH_REGIME.md). Names WITH a bundled transcript read it locally; names WITHOUT one (foreign small-caps) run as `general-purpose` agents that **WebSearch/WebFetch the latest transcript/results online** (tagged `transcript_source=web`; their conviction is capped if web evidence is thin — they never fabricate). Then the Director picks the apex 10 over ALL results. It writes `backend/_opus_debate/results_regime/<SYM>.json` per name and `backend/_opus_debate/apex_basket_opus_regime.json`. Wait for completion.
CONTINUITY LAYER (2026-07-08, after the 07-07 whiplash forensics): each re-debated name's input now embeds its own `prior_record` (last week's verdict/conviction/thesis) and the debate prompt REQUIRES a dated fact for any verdict flip or |conviction Δ|≥2 (`whats_changed_since_prior` in the output); a price-less input bundle (off-scan name) REQUIRES the agent to fetch the live FMP quote first (prep prints `GUARD price-blind bundles (...)` for visibility). Between Debate and Director the workflow runs the deterministic `continuity-gate` (diffs every fresh record vs `_archive_prev/`, stamps `continuity_flag` on unjustified flips; the Director is instructed to distrust flagged records and fall back to the ledger). Its summary line `continuity-gate: <N> diffed | <M> FLAGGED` is worth quoting in the final report.
ROBUSTNESS: some agent failures are tolerable. Run `python backend/_opus_debate/compact_table.py results_regime` to check coverage (rows should be ≈ TOTAL). Proceed if `apex_basket_opus_regime.json` has 10 picks and most names debated. STEP 3 — PUBLISH TO PRODUCTION GCS (idempotent). Run:
`python backend/_opus_debate/publish_to_frontend.py --gcs`

  `rebuilt per_methodology_baskets ... <~134> debated picks` and `overlaid with Opus debate: <~134> (no Opus debate yet: [])`
  `GCS push scans/speculair_baskets.json: OK`, `... speculair_apex_tracking.json: OK`, and `... speculair_debate_history/: OK`
If any push shows FAILED, re-run the SAME command once — it is idempotent (history dedups by run-date; tracking refreshes from GCS first; one publish = one rotation, so never publish twice in a run). If it prints `apex_basket_opus_regime.json has no picks` it aborts — go back and fix STEP 2.
